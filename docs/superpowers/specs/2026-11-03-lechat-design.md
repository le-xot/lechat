# lechat — дизайн

**Дата:** 2026-11-03
**Статус:** согласовано с заказчиком (окно, 7TV, отрисовка эмоутов)

## Зачем

Стрим идёт на две платформы: Twitch (`etonelexot`) и streamx (`le-xot`). Сейчас чаты читаются в двух окнах браузера. Нужно одно нативное окно с **одной общей лентой** сообщений, только чтение.

## Цели

- Одно окно, одна общая лента: сообщения Twitch и streamx вперемешку, по времени.
- Перед каждым сообщением — плашка источника: фиолетовый квадрат `T` (Twitch, `#9146FF`), зелёный `S` (streamx, `#00DC82`), с тултипом `платформа + канал`.
- Показ сообщений: время, ник цветом источника, текст, 7TV-эмоуты картинками (включая анимированные, широкие и zero-width), кликабельные ссылки.
- Устойчивое соединение: авто-реконнект, видимый статус каждого источника, без тихой потери сообщений.
- Конфиг со списком каналов — третий канал без перекомпиляции.
- Один бинарь, без бэкенда, БД и логина.

## Не-цели

Отправка сообщений, модерация, баны, реакции, ответы, бейджи, аватары, system-сообщения streamx, уведомления о сабах/рейдах, оверлей для OBS, разделение на колонки/панели, Windows/macOS-специфика, мобильные и веб-сборки.

## Анти-цели

- Приложение не должно требовать OAuth, Client-ID, API-ключей и сторонних аккаунтов.
- Не должно грузить CPU/память в простое: никакого постоянного repaint, анимация только для видимых эмоутов и по таймеру кадра.
- Не должно молча терять сообщения при реконнекте.

## Проверенные источники данных

### Twitch — анонимный IRC (read-only)

- `wss://irc-ws.chat.twitch.tv:443`
- `PASS oauth:justinfan<rand>` → `NICK justinfan<rand>`
- `CAP REQ :twitch.tv/tags twitch.tv/commands`
- `JOIN #etonelexot`
- Проверено живьём: приходит `ROOMSTATE` (`room-id=1263747798`), в шумном канале — `PRIVMSG` с тегами `display-name`, `color`, `badges`, `emotes`, `tmi-sent-ts`, `id`.
- Нативные эмоуты: `https://static-cdn.jtvnw.net/emoticons/v2/{id}/default/dark/1.0`, позиции из тега `emotes`.
- Сервер шлёт `PING` — отвечаем `PONG`.
- Бейджи приходят только именами (`subscriber/66`), картинку без Helix не достать → не рисуем.

### streamx — GraphQL

- HTTP: `POST https://streamx.satont.dev/api/query`
- WS: `wss://streamx.satont.dev/api/query`, протокол `graphql-transport-ws`
- `fetchUserByName(name)` → `id` (у `le-xot`: `30b9ec57-9ef7-4992-b114-f0f380bc60f6`)
- `chatMessagesLatest(channelID, limit)` — история
- `getEmotes(channelID)` — эмоуты канала (7TV CDN, `//cdn.7tv.app/...`, нужен `https:`)
- подписка `chatMessages(channelID)` — живые сообщения; авторизация не требуется (в схеме у подписок нет `@isAuthenticated`, в резолвере проверки сессии нет)
- Сегменты: `TEXT`, `LINK`, `MENTION`, `EMOTE`; поля `senderColor`, `createdAt`, `id`.
- API неофициальный и внутренний: может измениться без предупреждения. Отсюда — устойчивый парсинг, unknown-сегменты как текст, реконнект.

### 7TV

- `GET https://7tv.io/v3/users/twitch/{twitch_user_id}` → `emote_set.emotes[]`
- `GET https://7tv.io/v3/emote-sets/global`
- Элемент сета: `name` (он же алиас), `flags` (бит 1 = zero-width), `data.animated`, `data.host.url` + `data.host.files[]` (`1x.webp`…`4x.webp`, `static_name`, `width`, `height`).
- Канальный сет перекрывает глобальный по имени.
- Анимированный WebP: `image-webp` умеет `is_animated()`, `num_frames()`, `read_frame(&mut buf) -> u32` (мс).

## Решения

**Стек:** Rust 1.99, eframe/egui 0.37, egui_extras 0.37 (`http`, `image`, `webp`), tokio 1.54, tokio-tungstenite 0.30, reqwest 0.13 (rustls), serde/toml, chrono, tracing.

**Потоки:** UI в главном потоке (eframe). Каждая панель — tokio-таск, шлёт `ProviderEvent` в `tokio::sync::mpsc`; UI вычитывает канал раз в кадр и вызывает `ctx.request_repaint()` на новом событии.

**Модель сообщения** одинаковая для платформ:
`Message { id, platform, author: { name, color }, parts: Vec<Part>, ts_ms }`,
`Part::{ Text(String), Emote { uri, aspect, zero_width }, Link(String) }`.

**Отрисовка эмоутов:** высота = 1.5 высоты строки текста, ширина по пропорции исходника; масштаб файла выбирается по `pixels_per_point` и нужной высоте; zero-width рисуется без отступа и уменьшенным; при ошибке декода — `static_name`, при ошибке загрузки — текст-фолбэк.

**Анимация:** свой `ImageLoader` (копия egui-шного `GifLoader`), который распаковывает все кадры WebP, кладёт `FrameDurations` в `ctx.data` и отдаёт кадр по индексу из `uri#N`. egui сам планирует `request_repaint_after` по длительности кадра.

**UI:** одно окно, одна лента, минимальный размер окна 720×520, геометрия запоминается через eframe `storage`. В шапке — статус каждого источника: плашка, канал, цветная точка, тултип с последней ошибкой. Строка сообщения: плашка источника, `ЧЧ:ММ`, ник цветом, части. Выделение текста включено, ссылки кликабельны (`ui.hyperlink`). «Прилипание к низу» с порогом 64px; если пользователь выше — новые сообщения копят счётчик и показывается кнопка «↓ N новых». Максимум 500 записей, дедуп по `(platform, id)`.

**Конфиг:** `~/.config/lechat/config.toml`, генерируется при первом запуске. Панели: `kind = "twitch" | "streamx"`, `channel`, опционально `base_url`. Ошибки конфига показываются в окне, а не падают молча.

**Надёжность:** реконнект с экспоненциальным бэкоффом 1→30с; Twitch после реконнекта просто продолжает (истории нет), streamx перезапрашивает `chatMessagesLatest` и склеивает по `id`; дедуп по `id` в панели; кольцевой буфер 500.

## Решения после проверки дизайна независимым билдером

- **Каталог эмоутов — на источник, не глобальный.** 7TV-каталог собирается внутри Twitch-провайдера (канал по `room-id` + global) и живёт в его источнике. streamx не нуждается в матчинге: сервер уже отдаёт `EMOTE`-сегменты, поэтому `getEmotes` в v1 не грузится. Два Twitch-канала в конфиге не смешивают эмоуты.
- **Zero-width — наложение.** Рисуется поверх предыдущего эмоута, без собственной ширины, масштаб ~0.5 от высоты строки; если стоит первым в строке — рисуется инлайном уменьшенным. Это стандартное поведение 7TV, а не «просто без отступа».
- **Ссылки в Twitch.** `http://`/`https://` в тексте автоматически становятся `Part::Link`, хвостовая пунктуация (`.,!?)]`) отрезается от ссылки. Это не только streamx.
- **Пропуск сообщений виден.** При обрыве Twitch/streamx в панель вставляется системная строка «соединение потеряно, часть сообщений пропущена», а не тихий пропуск. Модель получает `Entry::{Msg, Note}`.
- **Реконнект streamx без переупорядочивания.** История запрашивается с `limit = 500`, живые кадры буферизуются до применения истории, затем всё сливается по `createdAt` с дедупом по `id`. Если история не пересекается с последним известным сообщением — системная строка о пропуске.
- **Общая лента.** Сообщения обоих источников вставляются в один `VecDeque<Entry>` по `ts_ms` (при равенстве — в порядке прихода); дедуп по `(platform, id)`, лимит 500 общий. Плашка источника рисуется в каждой строке, поэтому принадлежность видна и после прокрутки.
- **Анимация всегда включена** (по просьбе заказчика): чекбокса нет, кадры анимированных эмоутов идут с частотой не выше ~16 fps, вне вьюпорта эмоуты не рисуются и не планируют перерисовку.
- **7TV при сбое.** Ошибка загрузки каталога не блокирует чат: эмоуты показываются текстом, повтор — при реконнекте, по F5 и один отложенный через 60 секунд.

## Что остаётся на усмотрение реализатора

Точные размеры отступов и цвета темы, текст сообщений об ошибках, внутренняя раскладка модулей в рамках описанной структуры, выбор крейта для форматирования времени (`chrono`), названия тестов.
